## 1. 作业目标与交付边界

系统通过手机网页上传人脸照片，由云端服务器检索已登记人脸并完成签到。**签到不要求登录，也不依赖设备号、客户端填写的姓名或学号来确定身份**。注册时填写姓名、学号、用户名、密码并上传标准人脸照；登录后可查看记录；管理员可查看人员和全部签到记录，最终可维护照片库。服务器部署于云端，通过公网访问，并展示对同时到达的请求如何限流或排队。

本项目调用华为云 FRS，不训练或自行部署人脸检测与编码模型。课程演示使用获得授权的照片，不将原图、访问密钥、密码或数据库提交至 GitHub。单张静态照片不能证明现场真人在场，因此系统的结论是“照片与已登记人脸匹配”；活体防伪是可扩展能力，不把它写成已实现功能。

## 2. 技术选型

| 层次 | 选型 | 选择原因 |
| --- | --- | --- |
| 手机端 | 原生 HTML、CSS、JavaScript 的响应式网页 | 无需安装 App，手机浏览器可打开；便于三周内展示 |
| 服务端 | Python 3 + FastAPI + Uvicorn | 直接使用已验证的华为云 Python SDK；文件上传与 API 开发简洁 |
| 人脸服务 | 华为云 FRS，区域 `cn-north-4` | 提供检测、人脸库录入、一对多搜索，避免自行部署推理模型 |
| 数据库 | 开发和单机演示：SQLite；有并发写入需求时：PostgreSQL | 先快速形成可运行闭环，再按实测负载升级 |
| 高并发 | 目标方案：Redis 有界队列、固定 Worker、全局 FRS 调用限速 | 避免请求高峰直接超过云服务 QPS；目前尚未接入 |
| 云部署 | 华为云 ECS + 弹性公网 IP + Nginx + HTTPS | 满足公网访问、反向代理和手机拍照需求 |

浏览器的 `getUserMedia()` 相机接口要求安全上下文；公网演示应使用 HTTPS。当前页面使用文件输入的 `capture="user"` 让手机调用前置相机，并允许选取已有照片作为兼容方式。是否直接弹出相机由浏览器决定，须在目标手机上实测。[MDN 相机安全上下文说明](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)

## 3. 系统架构与请求流

### 3.1 当前已实现的单机闭环

```text
手机网页（frontend）
    │ 同源 HTTP 请求；公网阶段改 HTTPS
    ▼
FastAPI（backend.main）
    ├─ 注册 / 登录 / 注销 / 查询
    ├─ SQLite：users、sessions、checkins
    └─ HuaweiFaces 适配器（backend.faces）
            └─ 华为云 FRS：检测、录入、人脸搜索
```

目前 `POST /api/register` 和 `POST /api/checkins` 是同步请求，等待 FRS 返回后再给手机反馈。这样便于完成（2）（3）的功能演示，但同时大量签到可能导致请求排队或超出 FRS 配额。

### 3.2 目标云端架构

```text
手机浏览器 ── HTTPS ──> ECS 弹性公网 IP / Nginx
                              │
                              ▼
                         FastAPI API
                         ├─ 登录和管理员权限
                         ├─ 活动、人员和照片管理
                         ├─ 签到任务接收 / 状态查询
                         └─ 记录查询和导出
                              │        │
                              ▼        ▼
                         数据库     Redis 有界队列
                                       │
                                       ▼
                                 识别 Worker + 限速器
                                       │
                                       ▼
                                华为云 FRS 人脸库
```

目标流程中，API 接收并检查图片后返回随机任务 ID，Worker 调用 FRS；手机轮询任务状态并显示结果。任务完成或超时后删除临时照片。若队列未按期完成，保留现有同步接口用于课程规模演示，并用有界并发与明确的“忙碌，请重试”反馈保护服务；不要对外宣称已实现异步队列。

## 4. 人脸模型与身份识别

### 4.1 云服务接口分工

| 操作 | 华为云 SDK 接口 | 本系统负责的判断 |
| --- | --- | --- |
| 登记照检查 | `DetectFaceByFile` | 要求恰好一张清晰人脸，限制文件类型和大小 |
| 入库编码 | `AddFacesByFile` | 将随机 `external_image_id`、FRS `face_id` 与本地用户绑定 |
| 签到检索 | `SearchFaceByFile` | 从整个人脸库选最佳候选，应用相似度门槛和身份映射 |
| 两张照片实验 | `CompareFaceByFile` | 仅用于先前 SDK 实验；不能代替一对多签到检索 |

FRS 的人脸库保存人脸特征，云服务完成特征编码和检索；具体网络层数、权重和训练数据未由接口公开，报告不声称使用了某个自行部署的 CNN。[华为云 API 概览](https://support.huaweicloud.com/api-face/face_02_0052.html)、[Python SDK](https://support.huaweicloud.com/sdkreference-face/face_04_0021.html)

### 4.2 匹配规则

`SearchFaceByFile` 返回按相似度排序的候选。本地配置当前初值为 `FRS_MATCH_THRESHOLD=0.93`；若有第二候选，最高分还需比第二名至少高 `FRS_MATCH_MIN_GAP=0.03`。通过后按 `face_id` 找到本地用户。低分、近分、查无此人或未登记，均不写入成功签到。0.93 是官方建议的初始阈值，不等于在本组样本上已经验证的最优值。[华为云人脸搜索 API](https://support.huaweicloud.com/api-face/face_02_0086.html)

登记照限定一张人脸。签到照也应要求一张人脸；当前代码仅校验文件格式，FRS 搜索若收到多人照片会取最大的人脸，因此**签到照单人脸校验仍待补充**。无脸照片应明确显示“未识别到人脸”，不能被展示为系统故障。最终以经授权的同人不同照、不同人照片验证阈值、误识别与拒识。

### 4.3 数据与照片处理

手机上传 JPG/PNG，当前服务端限制 2 MB；SDK 调用期间临时写入 `data/private/`，调用结束删除。数据库不保存人脸原图，只保存 FRS 人脸 ID、随机外部图片 ID 和人员信息。由于管理员照片维护尚未实现，后续删除或替换照片时必须同时更新 FRS 人脸库与本地映射，处理任一方失败时的补偿，避免“云端有特征、本地无人”的残留。

## 5. 功能设计与页面

### 5.1 注册并录入信息

注册页填写姓名、学号、用户名、密码，上传清晰单人正面照。服务端检查必填、密码至少 8 位、学号/用户名唯一、文件类型和大小；先调用 FRS 检测及入库，再保存本地用户和 `face_id` 映射。成功提示姓名与学号，失败给出可理解的错误。当前实现为开放注册；正式演示要防止任意人冒用他人身份注册，可限制注册时间、人工审核或由管理员执行录入。

### 5.2 登录和注销

用户名/密码登录，服务端使用带随机盐的 PBKDF2 哈希验证密码，创建随机会话令牌；浏览器保存 `HttpOnly`、`SameSite=Lax` Cookie。注销删除服务端会话并清除 Cookie。公网 HTTPS 部署时启用 `COOKIE_SECURE=1`。普通用户只可查本人的记录；管理员可查人员列表和全部记录。管理员账号通过服务器上的 `python -m backend.make_admin 用户名` 提升，不能由公开注册接口直接申请管理员权限。

### 5.3 无登录签到与反馈

打开签到页 → 拍照或选照 → 上传 → FRS 一对多搜索 → 校验最高相似度和本地人员映射 → 写入记录 → 返回反馈。反馈分为“签到成功”“今日已签到”“未找到已登记人员”“照片不合规”“服务忙碌/失败”。当前按北京时间自然日对每个用户只记一次，SQLite 唯一约束 `(user_id, day)` 防止重复点击产生两条成功记录。手机端不传姓名或学号作为识别依据。

### 5.4 记录和照片库管理

登录用户在“我的签到记录”查看自己的日期和时间；管理员页面查看已登记人员与全部记录。目标版本增加按学号/日期筛选、CSV 导出、照片替换和删除、签到活动的开始结束时间。照片管理与活动管理当前未实现，不应在（2）演示中描述为已完成。

## 6. 前后端接口约定

**当前接口**（见 `backend/main.py`）：

| 方法与路径 | 登录要求 | 输入 | 主要返回 |
| --- | --- | --- | --- |
| `GET /api/health` | 无 | 无 | `status: ok` |
| `POST /api/register` | 无 | multipart：`username`、`full_name`、`student_id`、`password`、`photo` | `201`、登记信息、`face_enrolled` |
| `POST /api/login` | 无 | JSON：`username`、`password` | 登录 Cookie、姓名 |
| `POST /api/logout` | 无 | Cookie（若有） | `logged_out` |
| `GET /api/me` | 用户 | Cookie | 当前用户与 `is_admin` |
| `POST /api/checkins` | 无 | multipart：`photo` | `success` / `already_checked_in` / `unregistered` |
| `GET /api/records` | 用户 | Cookie | 本人签到记录 |
| `GET /api/admin/users` | 管理员 | Cookie | 已登记人员列表 |
| `GET /api/admin/records` | 管理员 | Cookie | 全部签到记录（当前最多 500 条） |

**目标增量接口**由三人在实现前共同确定：`POST/GET /api/events`（管理员活动管理）、`POST /api/events/{event_id}/checkins`（按活动签到）、`GET /api/checkin-tasks/{task_id}`（异步状态）、照片删除/替换和记录导出。新增接口时保持旧接口可运行，直到手机端切换并完成集成测试。

常见 HTTP 状态：`400` 图片或参数错误，`401` 未登录，`403` 权限不足，`409` 用户名/学号重复，`413` 图片过大，`502` FRS 调用失败，`503` FRS 环境变量未配置。网络错误不能显示为“未录入人员”。

## 7. 数据库设计

### 7.1 当前 SQLite 结构

| 表 | 关键字段 | 约束与用途 |
| --- | --- | --- |
| `users` | `id`、`username`、`full_name`、`student_id`、`password_hash`、`face_id`、`external_image_id`、`is_admin`、`created_at` | 用户名、学号和人脸 ID 唯一；映射云端人脸 |
| `sessions` | `token_hash`、`user_id`、`expires_at` | 只保存会话令牌哈希；注销时删除 |
| `checkins` | `id`、`user_id`、`day`、`checked_at`、`similarity` | `(user_id, day)` 唯一；记录签到与相似度 |

### 7.2 目标扩展

增加 `events(id, name, starts_at, ends_at, status)`；将 `checkins` 唯一键改为 `(event_id, user_id)`；增加 `face_images(id, user_id, face_id, external_image_id, created_at, status)` 支持一人多张登记照和照片维护。异步方案增加 `checkin_tasks(id, event_id, status, result, created_at, expires_at)`。若在 ECS 上使用多 Worker 并发写入，迁移到 PostgreSQL，并以数据库事务及唯一约束保证幂等；迁移脚本及演示数据由后端负责人维护。

## 8. 并发、性能与成本

华为云文档列出的普通 FRS 接口默认限额为 10 QPS，超出可能出现 `FRS.0033`。[华为云 FRS 计费说明](https://support.huaweicloud.com/productdesc-face/face_01_0016.html) 因此不能简单增加 Web 进程数就声称解决了高并发；多进程总调用量仍需受同一配额约束。

目标处理策略：API 限制每次图片大小；入队前限制单 IP 短时提交频率；Redis 队列设置上限；Worker 数固定；跨 Worker 共享令牌桶把 FRS 搜索调用控制在初始 8 QPS（留出其他接口余量）；对可重试的限流/网络错误做有上限的指数退避。队列满返回明确的重试提示，不无限等待。数据库唯一键处理同一人重复签到。请求量长期超过云端配额时，需申请更高 QPS 或缩小演示负载；不能仅靠排队保证无限吞吐。

压测先用模拟 FRS 响应覆盖 1、10、30、50 个并发上传，再用少量真实请求核对时延与费用；记录成功率、错误码、排队时间、P95 总响应时间、重复记录数。登记、检测、搜索的实际调用次数均应计入费用估算，不在压测中无限调用真实付费接口。

## 9. 云端部署与安全

1. 在 `cn-north-4` 确认 FRS 已开通、IAM 用户有检测/人脸库/搜索权限；用独立访问密钥配置 ECS 环境变量。首次部署运行 `python -m backend.setup_frs` 建库，后续不重复创建。
2. ECS 绑定弹性公网 IP；仅开放 Web 所需端口，对数据库和 Redis 不开放公网入口。Nginx 将 HTTPS 请求转发至本机 Uvicorn。部署域名和证书方式由云端负责人确定，并在真实手机浏览器上验证拍照上传。
3. 运行服务时设置 `HUAWEICLOUD_SDK_AK`、`HUAWEICLOUD_SDK_SK`、`FRS_REGION`、`FRS_FACE_SET`、`COOKIE_SECURE=1`。不得写入仓库或截图。定期备份数据库，清理临时照片与过期会话。
4. 管理接口检查服务端权限；照片、学号、签到记录只在必要范围展示。静态照片可被翻拍，演示中说明该限制；如果增加活体检测，需单独评估接口费用和时延。

当前代码尚未完成云端部署和并发保护，**不能直接作为公开互联网生产服务**。公网演示前需完成真实 FRS 调用、HTTPS、错误处理、请求速率限制及隐私检查。

### 演示脚本与截图位置

1. **注册并录入信息：** 数据库 `users` 原有计数 → 手机注册页输入基本信息并上传标准照 → 页面显示录入成功 → `users` 计数增加，FRS 返回 `face_id` 已映射。
2. **录入人员签到：** 使用该人另一张当天实拍照 → 手机显示签到成功和时间 → `checkins` 增加一条 → 登录后在记录页看到该条；再次提交显示“已签到”，条数不变。
3. **未录入人员签到：** 使用未登记、已授权的另一人照片 → 手机显示“未找到已登记人员” → `checkins` 条数不变。
4. **注销与权限：** 注销后打开记录页需重新登录；普通用户不能查看管理员接口。

演示前在目标手机、目标公网地址和正式云账号上完整排练一次。截图包含页面状态和数据库变化，但不要出现真实密钥；人脸照片与学号若用于对外展示，应征得当事人同意并按课程要求遮盖。

## 11. 当前进度与剩余工作

截至本文编写，仓库已有手机页面、FastAPI 接口、SQLite 表、华为云 FRS 适配器及人脸库初始化脚本；本地**模拟 FRS** 的注册、登录、注销、已录入/未录入签到和记录查询测试通过。完整设计中的活动管理、照片替换/删除、异步队列、全局限速、数据库迁移、ECS/HTTPS 和真实手机云端演示尚未完成。真实 FRS 可能返回“无人脸”等业务错误，仍需以实际云端响应校准页面反馈。

第一优先级是完成真实云端“登记 → 搜索 → 签到”闭环并取得（2）（3）要求的截图；其后根据助教演示需求补齐管理功能与高并发处理。
