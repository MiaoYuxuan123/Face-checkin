## 1. 项目目标

实现一个可通过公网访问的人脸签到系统。学生使用手机网页拍照并上传，无需登录或填写学号；服务器在已登记的人脸库中检索身份，匹配成功后写入签到记录并返回结果。管理员登录后可以维护人员及照片库、查看和导出签到记录。

本次设计以课堂演示规模为目标：先实现完整端到端流程，再通过压测展示并发请求的排队、限流和恢复。识别结果只用于本课程演示；照片与特征属于敏感数据，实验使用已获授权的照片。

## 2. 总体架构

```text
手机浏览器 ──HTTPS──> Nginx（ECS 公网 IP）
                         │
                         ▼
                    Python Web API
                    ├─ 管理员登录与权限检查
                    ├─ 人员及照片库管理
                    ├─ 签到任务与结果查询
                    └─ 签到记录查询
                         │       │       │
                         ▼       ▼       ▼
                    数据库    Redis 队列  华为云 FRS 人脸库
                                  │
                                  ▼
                           识别 Worker
```

服务端计划使用 FastAPI，手机端使用响应式网页，数据库先用 SQLite 完成开发和单机演示，云端按并发测试结果改用 PostgreSQL。Redis 负责签到任务队列及短时限流；Worker 从队列取照片，通过华为云 Python SDK 调用人脸搜索。ECS 绑定弹性公网 IP，对外开放 HTTPS 入口，数据库和 Redis 只允许内网或本机访问。AK/SK 只放在服务器环境变量中。

手机浏览器调用相机需要安全上下文，因此公网演示要配置 HTTPS；仅用 `http://公网IP` 打开网页不能保证浏览器相机接口可用。也可使用系统相机拍照后通过文件选择框上传，作为兼容路径。

## 3. 模型选择与识别方案

**选型：华为云 FRS 托管人脸识别服务。** 系统通过 SDK 调用 `DetectFaceByFile` 检查照片中的人脸及位置，通过 `AddFacesByFile` 将登记照写入云端人脸库，通过 `SearchFaceByFile` 对签到照进行一对多检索。人脸编码和检索由 FRS 完成，应用只处理接口返回的人脸 ID、相似度和人员映射。已有的 `detect_face.py` 和 `compare_face.py` 可用于接口连通性与图片质量实验。云服务未公开具体网络结构与模型权重，本设计只选择可验证的服务能力，不将其写成某个自部署 CNN。华为云文档明确将人脸库定义为存储人脸特征的资源，并提供人脸检测与搜索接口。[API 概览](https://support.huaweicloud.com/api-face/face_02_0052.html)

使用 FRS 的原因是本组已完成该服务的检测、比对 SDK 实验；服务端无需准备 GPU、模型权重和推理环境，三周内可以集中完成照片管理、身份映射、签到记录、公网部署及并发处理。`CompareFaceByFile` 仅比较指定的两张照片，无法独立解决“手机不提供身份时从全库找人”的要求；签到流程必须使用人脸搜索。

初始阈值设为 0.93，来源于华为云接口建议值；这是待验证参数。用本组授权样本制作“同一人不同照片”和“不同人照片”测试集，记录误识别与拒识情况，再决定最终阈值。若最高分低于阈值，或前两名分数接近，则返回“未能确认身份”，不自动签到。每张登记照和签到照均要求画面中只有一张清晰人脸，因为官方搜索接口在多张人脸时会选最大人脸。可在上传阶段进行人脸数量与图片大小检查。

最终模型评估以实测为准：在已获授权的少量登记照和签到照上统计正确识别率、误识别率、拒识率和接口延迟，并展示典型成功与失败案例。报告中分别说明“云端负责的人脸检测/特征编码/检索”和“本组实现的业务判断/并发控制”，避免将云端模型的内部实现归为本组成果。

## 4. 功能与流程

### 4.1 管理端

管理员登录后创建签到活动，维护人员资料，上传或删除登记照。上传时先检查格式、大小、清晰度和单人脸要求；成功写入 FRS 人脸库后，在本地保存 `person_id`、`face_id`、`external_image_id` 的映射。管理员可按活动、时间和人员筛选签到记录，并导出 CSV。

### 4.2 无登录签到

手机打开活动链接，授权相机拍照或选择照片，上传到 `POST /api/events/{event_id}/checkins`。服务端验证活动是否开放、文件是否合规，为请求生成任务 ID 并返回“处理中”。Worker 调用 FRS 搜索，校验相似度与身份映射，在数据库中对 `(event_id, person_id)` 建唯一约束，原子地写入首次成功签到时间。客户端轮询 `GET /api/checkins/{task_id}`，显示“签到成功：姓名/时间”“已签到”“未识别”或“稍后重试”。姓名反馈只显示必要信息。

不依赖手机设备号或客户端声明的姓名确定身份。前端重复点击、网络重试或同一个人重复拍照均不能产生重复签到记录。

### 4.3 数据设计

| 表 | 主要字段 | 用途 |
| --- | --- | --- |
| `admin_users` | id、用户名、密码哈希、角色 | 管理端认证 |
| `persons` | id、姓名、学号、状态 | 被签到人员 |
| `face_images` | id、person_id、FRS face_id、external_image_id、录入时间 | 照片与人脸库映射 |
| `events` | id、名称、开始/结束时间、状态 | 签到活动 |
| `checkins` | id、event_id、person_id、签到时间、相似度 | 成功签到记录 |
| `checkin_tasks` | id、event_id、状态、结果、创建时间 | 异步任务与反馈 |

原始签到照片仅用于本次识别，处理后尽快删除；登记照只对管理员开放，并支持删除人员时同步删除对应的人脸库数据。日志不记录原图、AK/SK 或完整人脸特征。

## 5. 高并发处理与验证

华为云 FRS 文档列出的普通接口默认上限为 10 QPS，超限可能返回 `FRS.0033`。服务器侧为 FRS 调用设置低于配额的速率限制（初始 8 次/秒，按实测调整）、固定数量 Worker 和有界队列。队列满时明确返回“当前人数较多，请稍后重试”，不无限积压；临时失败可短次数退避重试。数据库唯一约束保证并发请求不会重复写入。

压测分别覆盖 1、10、30、50 个同时提交的模拟请求；记录请求接受率、排队时长、签到成功率、P95 反馈时间、FRS 限流次数和重复记录数。测试优先使用模拟 FRS 响应，少量真实调用验证端到端流程，以控制费用。若真实目标负载长期超过默认配额，需要申请更高 QPS 或缩小本次演示规模。

## 7. 风险与验收标准

- **误识别与冒用**：单张静态照片可能被翻拍冒用。基础版提供清晰照片检查、阈值与人工复核路径；若课程要求防伪，再评估活体检测接口。
- **无登录入口被滥用**：限制图片大小、活动有效期、单 IP 提交速率和队列长度；限制查询接口只能用随机任务 ID 获取必要结果。
- **照片及凭证泄露**：管理员密码哈希保存，管理接口鉴权；使用 HTTPS，AK/SK 不进入仓库；定期清理照片与任务数据。
- **云资源限制**：先核对 FRS 已开通、区域和权限，再测实际 QPS、费用及 ECS 规格。

最终验收以手机公网访问、无登录拍照签到、服务器端检索身份、成功反馈、管理员管理照片及查看记录、重复签到不重复写入、并发测试有证据为准。
